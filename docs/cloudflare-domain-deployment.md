# Cloudflare deployment for agdlawai.com

## Current Cloudflare state

- Zone: `agdlawai.com`
- Zone status: active
- Zone type: full
- Cloudflare nameservers: `dion.ns.cloudflare.com`, `gracie.ns.cloudflare.com`
- Deployment target: Cloudflare Workers with OpenNext for the Next.js frontend

The backend remains a Node.js API service. Deploy it to a Node-capable host and expose it as `https://api.agdlawai.com`, or plan a separate Cloudflare Containers/Workers migration.

## Frontend deployment

The frontend is configured by `frontend/wrangler.jsonc`.

Local deploy:

```bash
cd frontend
npm ci
npm run lint
npm run build
npm run deploy
```

GitHub Actions deploy:

1. Add repository secrets:
   - `CLOUDFLARE_ACCOUNT_ID`
   - `CLOUDFLARE_API_TOKEN`
2. Add repository variables:
   - `NEXT_PUBLIC_APP_URL=https://agdlawai.com`
   - `NEXT_PUBLIC_API_BASE_URL=https://api.agdlawai.com`
   - `NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_DEFAULT_KEY=your-publishable-key`
3. Run the `Deploy frontend to Cloudflare` workflow manually, or merge to `main`.

The Worker config attaches both custom domains:

- `agdlawai.com`
- `www.agdlawai.com`

## Backend API

Required production backend env:

```bash
NODE_ENV=production
PORT=3001
FRONTEND_URL=https://agdlawai.com
FRONTEND_URLS=https://agdlawai.com,https://www.agdlawai.com
BACKEND_PUBLIC_URL=https://api.agdlawai.com
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_SECRET_KEY=your-service-role-key
DOWNLOAD_SIGNING_SECRET=replace-with-a-random-32-byte-hex-string
USER_API_KEYS_ENCRYPTION_SECRET=replace-with-a-long-random-secret
MOYASAR_SECRET_KEY=sk_live_...
MOYASAR_WEBHOOK_SECRET=replace-with-moyasar-webhook-secret-token
BILLING_CRON_SECRET=replace-with-a-random-cron-secret
SUPER_ADMIN_EMAIL=jabosaag@gmail.com
```

Create a proxied DNS record for `api.agdlawai.com` that points at the backend host. Keep service-role keys and provider secrets only on the backend host.

## Supabase Auth and Google OAuth

Supabase Auth settings:

- Site URL: `https://agdlawai.com`
- Additional redirect URLs:
  - `https://agdlawai.com/*`
  - `https://www.agdlawai.com/*`
  - `http://localhost:3000/*`

Google Cloud OAuth settings:

- Authorized JavaScript origins:
  - `https://agdlawai.com`
  - `https://www.agdlawai.com`
  - `http://localhost:3000`
- Authorized redirect URI:
  - `https://your-project-ref.supabase.co/auth/v1/callback`

Use the Supabase project ref for the redirect URI. Do not use `https://agdlawai.com/auth/v1/callback` for Supabase-managed Google OAuth.

## Moyasar callbacks

Configure Moyasar to call:

- Webhook URL: `https://api.agdlawai.com/billing/moyasar/webhook`
- Success URL generated by backend: `https://agdlawai.com/billing?checkout=success`
- Failure URL generated by backend: `https://agdlawai.com/billing?checkout=failed`

## Verification checklist

1. `https://agdlawai.com` loads the Cloudflare Worker.
2. `https://www.agdlawai.com` loads or redirects consistently.
3. Browser network calls go to `https://api.agdlawai.com`.
4. Backend `/health` returns `{ "ok": true }`.
5. Google sign-in returns to the AGDLAWAI domain, not the old BYR Agri AI project.
6. Supabase browser key is the publishable key only.
7. No service-role key, DB password, Moyasar secret, or provider API key appears in the frontend bundle or Git history.
